# Test vectors

| Directory | Contents | Provenance and license |
|---|---|---|
| `corpus/asn1tools/` | ASN.1 test specifications | asn1tools by Erik Moqvist, MIT (`LICENSE.asn1tools`), commit 3fdf723 |
| `corpus/ietf/` | IETF PKIX/CMS modules (RFC 1155–5280) | IETF Trust; code components under the Simplified BSD License |
| `corpus/derived/` | Specifications derived from the corpus (e.g. zforce without EXTENSIBILITY IMPLIED) | as the source |
| `cases/` | Random, constraint-satisfying values generated by `scripts/gen-cases.cs` (including `telemetry`, from `samples/telemetry`) | this repository |
| `ber/`, `der/`, `uper/`, `per/` (APER), `oer/`, `jer/` and `xer/` (with the JSON/XML `text`) | Encodings of `cases/` computed by asn1tools 0.169.0 (`scripts/asn1tools_vectors.py`) | computed data, MIT |

The example encodings of X.690, X.691 Annex A, X.693 Annex A, X.696 Annex A and X.697 Annex A used by the tests are
quoted from the ITU-T recommendations (02/2021). Where asn1tools deviates from those texts, the tests follow the
standard; the deviations are listed in [ADR 0003](../docs/decisions/0003-standards-editions.md).

Large third-party specifications (3GPP, ETSI, OMA, IEEE, CEN) are not committed. `scripts/fetch-extended-corpus.sh`
downloads them into `.cache/` for `ExtendedCorpusTests`.

Regenerating:

```sh
python3 -m venv .venv && .venv/bin/pip install asn1tools
dotnet run scripts/gen-cases.cs -- <name> <count-per-type> <seed> <spec.asn>...
.venv/bin/python scripts/asn1tools_vectors.py --codecs ber,der,uper,per,oer,jer,xer [name ...]
```
